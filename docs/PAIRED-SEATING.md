# Branch and batch seating

Open **Seating plans → Generate seating**, choose the examination cycle, then choose the date and shift.

1. Choose Group A and Group B. Each choice includes its branch, batch, year and semester, using the placement for the examination cycle. Different batches of the same branch are allowed, including first and third year.
2. Select that pair’s rooms. Only rooms belonging to the groups’ school are offered. The room list shows the actual available seats for each group, excluding disabled seats and respecting usable capacity.
3. Add another pairing for the next set of rooms. A room can belong to only one pairing in a seating version. The same group can continue in another pairing when necessary; students are assigned once, in the order the pairings appear.
4. Review the allocation preview. Students fill down each column in natural roll-number order. The two groups alternate between available columns, skipping columns that are entirely disabled. Roll numbers continue into subsequent selected rooms. Empty capacity in one group’s columns is not filled with another group.
5. Generate a draft, review it, and use **Download Excel** or **Print all rooms**. Publication requires all validation checks to pass.

Students from unselected groups and students without enough seats remain in the unallocated report. The application does not silently drop students or add a third group to a room. A draft with unallocated students cannot be published. A session containing only one group needs another compatible group scheduled in that session before it can use paired generation.

## Format

The supplied `Morning Shift seating plan 16-10-2026.xlsx` is the visual reference. The Excel export includes a master sheet and a sheet for each occupied room. Room sheets use the original fonts, cell styles, colour theme and invigilator marker. They include the three centred headings, bordered seat grid, centre aisle, desk labels below the seats, whiteboard, invigilator sides, three summary lines (extended when necessary), and the total. Worksheets have landscape A4 print setup and explicit print ranges.

Rows and columns come from the configured physical room, so a room with different geometry uses that geometry rather than inventing or collapsing seat positions. The 12-column reference layout also retains the original column widths. Disabled and vacant positions stay blank in the printed form. The browser offers the same structure with horizontal scrolling on narrow screens.

The summary contains the programme, batch, semester, exact roll ranges, course and actual number seated. Missing roll numbers split a range rather than implying that an absent student is assigned.

## Saved rules and history

No new database tables or columns are required. Pairings, the room-to-column group mapping, student group membership and display labels are saved in `seating_allocations.rule_profile`. Existing plans retain their stored assignments. Manual moves and unallocated resolutions must match the room’s school and saved group column; publication independently checks the rules. Published and superseded versions cannot be manually edited.

School ownership remains mandatory. Student progression continues to use the academic calendar and term records; pairing choices use the examination cycle’s placement rather than a later directory year. All regular department-assigned elective eligibility continues to cover the whole class.

## Verification

`tests/PairedSeatingTest.php` creates and removes an isolated test database. It checks same-branch/different-year and different-branch pairings, continuation across rooms, blocked columns, shortages, school boundaries, duplicate-room rejection, the actual generation and correction handlers, publication checks, physical seat positions, workbook package structure and rendered views. Existing school-room, end-to-end seating and department-elective tests also apply.

The sample files generated by the test use fictional students. They are written to the ignored `outputs/seating-redesign-20261024/` directory and are not inserted into the operational database.
